# 00 — 原始構想筆記

> 專案起點時的想法，保留原文作為參考。後續文件是對這份筆記的展開與回應。

最主要的功能還是在於說

1. 復原方便 switch
   git本身就是將世界切成好幾個平行時空的概念 因此蓋爛的時空並不會影響到原來的時空
   解決方法：
   其實就是在你的主線內切換世界回 哪一個時間點上
   目前的設計比較討厭的是 你如果按照這個世界開法 世界會越來越多 而且很龐雜 在自己世界下開世界會簡單很多
   可能就插件加個介面可以做到

2. 多人協作合併 merge
   衝突處理是最常用的功能 你有兩張地圖各自蓋不同東西 在合併的時候一般來說比較麻煩
   merge 在單人情況下 大部分時候是沒有衝突能夠直接合併回主線的
   但是衝突的時候 你就要選擇 這塊應該要用原本主線的 還是用你新分支的 或甚至你自己來調整
   如果沒有用git的設計的話 一般你合併下去想要復原就很麻煩
   解決方法：
   兩個世界做diff 告訴玩家哪邊不一樣 要使用主線 還是分支的 還是你自行更改
   這塊我認為應該要有一個像藍圖或Axiom那種方塊預覽介面會直觀很多

3. 存檔點把控 commit
   原來的用途會用commit 就是手動存檔一遍 讓系統知道你有一個停留點在這 之後除了可以切換branch 分支 之外 也可以退回這個commit 手動存檔點
   解決方法：
   寫一個插件讓玩家手動備份確立存檔點 (甚至自動一點 玩家登出時才備份該存檔點)
   至於每次commit是要存一整個世界還是 存區塊 這個還不知道

以下是其餘MC應該用不到的功能

> 註（2026-09-30）：「用不到」為筆誤。類 GitHub 的網頁檢視端是正式目標，見 [07](07-remote-hub.md)。

4. 雲端管理 (一般來說我們還會把專案直接push放到github上 這樣以後換電腦 換環境 甚至別人想要接著繼續開發 都可以直接在他們電腦上pull 下來 繼續接下來的開發)
